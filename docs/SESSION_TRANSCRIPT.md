### 一、 为什么它必须保持蓝牙连接？（底层原理限制）

这个项目的原理**不是**直接修改 iOS 系统里的定位坐标，而是把电脑伪装成一个 **MFi 认证的外部蓝牙 GPS 硬件配件**（通过蓝牙 RFCOMM 连接 iPhone 的 iAP2 服务 `00000000-deca-fade-deca-deafdecacafe`）：

1. **伪装硬件握手**（`Identification.cs` / `MfiSigner.cs`）：  
   连接建立后，服务端向 iPhone 发送 `0x1D01` 声明自己带有 `Group 22 (Location)` 硬件组件，并用内置的 MFi 证书链 + P-256 私钥完成 `0xAA00~0xAA05` 硬件认证。
2. **高频 NMEA 数据流喂送**（`LocationSession.cs`）：  
   认证通过后，iPhone 会下发 `0xFFFA (StartLocationInformation)` 订阅实时定位。服务端启动定时器，默认每 **250ms** 向手机发一次 `0xFFFB`（包含当前 UTC 时间戳的 `$GPGGA` / `$GPRMC` 卫星报文）。
3. **iOS `locationd` 的定位融合机制**：  
   iOS 之所以显示假位置，是因为它把你的电脑当成了外接的高精度 GPS 天线。**一旦蓝牙断开或停止发送 `0xFFFB` 报文超过数秒**，iOS 的 `locationd` 判定外接 GPS 硬件离线，会**立刻注销该定位源**，瞬间回退到手机自带的 GPS + Wi-Fi + 基站定位。

### 一、 `iap2loc` 改定位的完整底层原理（5 层协议拆解）

为什么 `iap2loc` 不需要越狱、也不需要开启 iOS 开发者模式就能改定位？  
因为苹果为 **车载 CarPlay 车机** 和 **外接专业蓝牙 GPS 天线（如 Garmin GLO、Bad Elf）** 设计了一套官方底层协议叫 **iAP2（iPod Accessory Protocol 2）**。当 iPhone 连上这类外部硬件时，iOS 允许外部硬件接管或参与系统 GPS 定位。

`iap2loc` 的本质，就是**用软件完整伪造了一个带有苹果 MFi 加密芯片的蓝牙 GPS 硬件**，全流程共 5 步：

#### 第 1 步：物理传输层连接（`BtRfcommTransport.cs`）

- iPhone 系统后台有一个常驻守护进程叫 `iap2d`，它在**经典蓝牙（Bluetooth Classic RFCOMM）**&#x4E0A;监听一个苹果专用的固定服务 UUID：  
  `00000000-deca-fade-deca-deafdecacafe`
- 电脑通过蓝牙连上手机的这个 UUID，建立一条双向字节流管道（类似无线串口）。

#### 第 2 步：iAP2 链路层握手与心跳（`Iap2Link.cs`）

- 连上后，电脑先发 6 字节唤醒魔数：`FF 55 02 00 EE 10`，iPhone 回复同样的 6 字节，确认双方讲的是 iAP2 协议。
- 随后双方发送 `FF 5A ...` 数据帧，通过 `ControlSync (0x80)` 协商包长度、重传超时，建立 **Control Session（控制会话，Session ID = 10）**。后续所有包都带序号 `seq` 和确认号 `ack`，断流超时链路就会销毁。

#### 第 3 步：谎报配件身份与 GPS 硬件能力（`Identification.cs`）

- iPhone 发送 `0x1D00 (StartIdentification)` 询问：“你是什么配件？”
- 电脑回复 `0x1D01 (IdentificationInformation)`，在报文里塞入两个关键声明：
  1. **Message 列表（参数 6 & 7）**：声明自己会接收 `0xFFFA（开始定位）` / `0xFFFC（停止定位）`，并会发送 `0xFFFB（NMEA 定位数据）`。
  2. **Group 22（LocationInformationComponent）**：向 iOS 注册自己拥有一颗外部 GPS 定位芯片。
- iPhone 检查格式无误，回复 `0x1D02 (IdentificationAccepted)`。

#### 第 4 步：过苹果 MFi 3.0 硬件加密认证（`MfiSigner.cs`）

- 苹果为了防止随便一个山寨蓝牙设备都能接管手机，要求配件必须搭载苹果官方的 **MFi 认证加密芯片**。
- iPhone 发送 `0xAA00` 索要芯片证书 → 电脑把从真芯片提取出来的证书链 `certificate.p7b`（`0xAA01`）发过去。
- iPhone 用内置的 Apple 根证书验明正身后，生成一个 **32 字节随机数（Challenge）** 通过 `0xAA02` 发给电脑。
- 电脑用配套提取出来的 **P-256 私钥（`identity.pk8`）** 对这 32 字节做 ECDSA 签名（并做 Low-S 归一化模拟硬件协处理器特征），通过 `0xAA03` 发回。
- iPhone 验签通过，回复 `0xAA05 (AuthenticationSucceeded)` —— **至此，iOS 彻底相信你是一个合法的苹果 MFi 外部 GPS 硬件！**

#### 第 5 步：每 250ms 持续喂 NMEA 卫星报文（`LocationSession.cs` + `Nmea.cs`）

- 认证一通过，iPhone 的定位守护进程 `locationd` 立刻发来 `0xFFFA (StartLocationInformation)`，要求配件按指定周期（通常 250ms~1000ms）上报 GPS 数据。
- 电脑启动定时器，每 250ms 把你在网页地图上选的经纬度，编码成标准的卫星串口报文（`$GPGGA` 和 `$GPRMC`），装进 `0xFFFB` 消息发给手机。
- 手机收到源源不断的 `$GPGGA/$GPRMC` 报文，系统定位就变成你设定的位置了。

### 二、 核心问题：电脑放家里，人在外面，能不能通过 HTTP / “远程蓝牙”改定位？

结合上面的第 1 步原理，我们先看**物理限制**，再看**怎么突破它**。

#### 1. 为什么“只有一台裸 iPhone 在外面 + 电脑在家里”无法直接走 HTTP 伪造 iAP2？

- 因为 iPhone 系统里的 `iap2d` 进程**只监听手机自己的物理蓝牙芯片（RFCOMM）和物理 USB 接口**，它**没有**监听任何 HTTP 或公网 TCP 端口。
- 在**未越狱**的 iPhone 上，哪怕你在手机浏览器里访问家里电脑的 HTTP 服务，或者在手机上装个 App 收到家里电脑发来的 HTTP 数据，**普通 App 也没有系统权限把收到的数据塞进 iOS 底层的 `iap2d` 或 `locationd` 里**。
- 换句话说：**iPhone 身边 10 米之内，必须有一个真实的蓝牙射频芯片跟它保持 RFCOMM 连接。**

### 一、 核心对比：你之前的项目 vs 现在的 `iap2loc`，底层差在哪？

iOS 系统的定位中心（`locationd` 守护进程）一共有 **4 个定位数据来源**，按系统信任的**优先级从高到低**排列如下：

|       优先级      | 定位通道                                     | 底层走什么协议                                                       | 能不能用小火箭 / HTTP 拦截伪造？                                            | 现状与致命点                            |
| :------------: | :--------------------------------------- | :------------------------------------------------------------ | :-------------------------------------------------------------- | :-------------------------------- |
| **第 1 级 (最高)** | **外接 MFi 硬件 GPS**<br />（即现在的 `iap2loc`）  | **物理蓝牙芯片 RFCOMM**<br />(`bluetoothd` → `iap2d` → `locationd`) | ❌ **不能纯靠软件 HTTP 伪造**<br />因为它完全不经过手机网卡和 TCP/IP 协议栈，小火箭根本碰不到蓝牙底层 | ✅ 最新 iOS 依然有效，优先级高于手机自带 GPS 卫星    |

|    **第 2 级**   | **手机内置 GPS 芯片**<br />(`GNSS` 硬件卫星)       | 手机主板基带芯片直连天线                                                  | ❌ 纯硬件物理接收天上卫星信号，无法拦截                                            | 只要在室外/窗边搜到卫星，就会覆盖掉第 3 级的网络定位      |
| **第 3 级 (最低)** | **Wi-Fi / 基站辅助定位**<br />（你之前的 `wloc` 项目） | **HTTPS 网络请求**<br />(`gs-loc-cn.apple.com/clls/wloc`)         | ✅ **能！**<br />正因为它是普通 HTTPS 请求，所以小火箭能 MITM 解密并替换 Protobuf 里的坐标  | ❌ 新版 iOS 失效/不稳定（原因见下方）            |

#### 为什么你之前的 `iOS-Location-Spoofer-Web` 可以纯走 HTTP，而 `iap2loc` 不行？

1. **之前的 `wloc` 方案是“手机主动发 HTTP 问苹果”**：  
   iPhone 为了查周围 Wi-Fi 路由器和基站在哪，会主动向 `gs-loc-cn.apple.com/clls/wloc` 发 HTTPS 请求。你的小火箭脚本在半路截住返回包，去你的 Cloudflare 网页拉取 `/loc.json` 的坐标塞进去。因为数据源本来就是 HTTPS，所以纯网络就能闭环。
